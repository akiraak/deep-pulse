# 「自分が作ったアプリで他人の人生を壊さないための7つの対策」― バイブコーディング時代のWebアプリ・セキュリティ最低ライン

ChatGPTやLovable、Cursor、v0で「とりあえず動いた、デプロイしちゃった」あなたへ。2025年7月、ある人気アプリは**運転免許証72,000枚**を全世界に公開していました。原因は、ハッキングではなく**ただの設定ミス**ひとつ。

> 元記事（グラフ・相関図付き）はこちら: https://akiraak.github.io/deep-pulse/articles/2026-05-06_非エンジニアのバイブコーディング_セキュリティWebアプリ編.html

## 読みどころ

- **5つの代表事件ギャラリー** ― Lovable BOLA（5回のAPIコールで他人のDB認証情報）、tea dating（免許証72,000枚公開）、Replit AIエージェントの本番DB削除事件など、2025〜2026年に立て続けに起きた事故を3行ドラマで一気に
- **数字で見る現実** ― AI生成コードの45%にOWASP Top 10脆弱性、AI共著コードは人間の2.74倍、公開デプロイされたバイブコード製アプリの5つに1つに重大欠陥
- **7つの落とし穴と7つの対策** ― APIキー漏洩 / DB直露出 / 認可バグ / SQLi・XSS / プロンプトインジェクション / Webhook偽装 / 料金暴走を、攻撃シーン → 仕組み → 例え話 → 対策 → AIへのコピペ用指示文の同じフォーマットで7組
- **準備運動のレベル判定フローチャート** ― 自分のアプリがレベル1（ローカル）〜レベル4（決済あり）のどこに居るかを判定して、必要な対策の数を決める
- **公開前チェックリスト 🟢🟡🔴** ― 本番公開ボタンを押す前に必ず通す15項目

「動いた」と「安全」は別の星に住んでいます。両方の住所を訪ねないと、アプリは"完成"しません。
