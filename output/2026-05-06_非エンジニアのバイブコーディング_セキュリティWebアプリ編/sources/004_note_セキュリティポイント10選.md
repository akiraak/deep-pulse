### バイブコーディング時代の光と影 {#756f7ce8-ec13-47b8-b038-89a1f3d716e5 name="756f7ce8-ec13-47b8-b038-89a1f3d716e5"}

AIツールによる開発支援が当たり前になった今、私たちは「バイブコーディング」の時代を生きています。ChatGPT、Claude、Cursorなどのツールを使えば、数時間で動くアプリケーションが作れる。これは素晴らしい民主化です。

しかし、ここに大きな落とし穴があります：

**1. 開発速度の向上がセキュリティ意識を置き去りにする**

-   「とりあえず動けばいい」という思考に陥りやすい

-   AIが生成したコードのセキュリティリスクを理解せずにコピペ

-   本番環境へのデプロイまでの時間が短縮され、テスト不足になりがち

**2. AIツールは「動くコード」は生成するが「安全なコード」とは限らない**

-   AIは要求された機能を実装することに最適化されている

-   セキュリティのベストプラクティスは、明示的に要求しない限り考慮されないこともある

-   生成されたコードの潜在的リスクを見抜く力が必要

**3. 開発の民主化により、セキュリティ知識が不足した開発者が増加**

-   非エンジニアでもアプリが作れる時代

-   基礎的なセキュリティ知識なしに本番環境にデプロイする危険性

-   「知らないことを知らない」状態での開発

以上のような危険を回避するために、開発する製品の性質に応じて、外部のセキュリティ診断を受けたほうが安全な場合があります。その判断基準について、全てを網羅しているわけではありませんが、以下に述べる10個のポイントを見れば、危険度を見積もることができるようになっています。

## バイブコーディングで意識すべきセキュリティポイント10選 {#a9d97efb-2d45-4473-93ac-f9a62ed71411 name="a9d97efb-2d45-4473-93ac-f9a62ed71411"}

### 1. 作るアプリを分類して、適切なセキュリティレベルを判定する {#35fe42a9-4ce1-45ef-a9a8-5336fe81379f name="35fe42a9-4ce1-45ef-a9a8-5336fe81379f"}

開発を始める前に、まず「どんなアプリを作るのか」を明確にしましょう。すべてのアプリに銀行レベルの厳重なセキュリティが必要なわけではありません。過剰なセキュリティは開発速度を落とし、不十分なセキュリティは致命的な問題を引き起こします。

**セキュリティレベル判定のチェックリスト：**

以下の7つのポイントが分かれ目となります。

1.  データを保存するか否か

2.  ユーザーは誰か（自分だけか、社内限定か、全世界か）

3.  ローカルで動くか、クラウドで動くか（※ローカルとは自分のPC内の閉じた環境のことです）

4.  会員登録機能の有無

5.  ユーザーがデータを作成できるか、読み取り専用か

6.  決済機能の有無

7.  外部サービス（Stripe、ChatGPT API等）との連携の有無

**フローチャートを作成しました。こちらのシナリオに照らし合わせて、セキュリティにどれぐらい力を入れるべきか判定するのが良いかと思います。**

![セキュリティチェックのフローチャート（筆者作成）](https://assets.st-note.com/img/1755600880-sr5ClB8TEAicKd490XbVvanS.png?width=1200){#586c658a-9667-4a4f-8759-110c322f50c6 height="434" loading="lazy" width="620"}

### 2. データベースは金庫のように扱う - 露出させない、バックアップを怠らない {#d03a495a-c295-46b0-86c6-bde207de503d name="d03a495a-c295-46b0-86c6-bde207de503d"}

データベースはアプリケーションの心臓部です。データベースの設定を間違えると、データの流出、改ざんなどの問題に繋がります。

**鉄則：**

-   **DBをインターネットに直接露出させない**\
    SupabaseというPaaSがあるのですが、これを通してデータベースを利用している方は要注意です。**本当に注意してください。**

-   **定期的な自動バックアップ**\
    週次・日次・リアルタイムなど、アプリの重要度に応じて設定しましょう。 万が一の事故に備えることができます。

### 3. バージョン管理をしてバグに備える {#3c7ac527-7974-4048-936d-5447929f34db name="3c7ac527-7974-4048-936d-5447929f34db"}

バージョン管理という概念があります。作成しているプロダクトにバグが生じる可能性があるんですが、その際に元々動いていたバージョンに簡単に戻すことができるのが利点です。

**メリット：**

-   変更履歴の完全な追跡（誰が、いつ、何を変更したか）

-   問題のあるバージョンから安全な状態への即座の復元

-   コードレビューによるセキュリティホールの早期発見

**要注意：** .envファイルなど、機密情報を含むファイルは必ず.gitignoreに追加しましょう。GitHubには自動的にシークレットキーを検知する機能もありますが、過信は禁物です。

### 4. APIキーは家の鍵と同じ - 絶対に露出させない {#a1ca0657-9172-41a4-8636-f1b18d56560f name="a1ca0657-9172-41a4-8636-f1b18d56560f"}

外部サービスとの連携で使うAPIキーの管理を徹底してください。パスワードと同じです。外部に流出すると非常に危険です。

**絶対NGな例：**

JavaScript

``` {#f3bee538-1e21-46e3-b205-7af1a899ae31 data-name="preCode"}
// これは絶対ダメ！
const openaiApiKey = "sk-xxxxxxxxxxxxx";
```

**正しい実装：**

JavaScript

``` {#568f9190-12fa-470c-a95d-1afc38d56585 data-name="preCode"}
// 環境変数から読み込む
const openaiApiKey = process.env.OPENAI_API_KEY;
```

特にフロントエンド（React、Vue.js等）のコードにAPIキーを埋め込むと、そのAPIキーを誰でも使えるようになって、一瞬でクレジットが飛びます。必ずバックエンドのAPIを経由する構成にしましょう。

### 5. クラウドの利用料金にアラートを設定する {#ffbd1dda-05d3-48c5-8e12-13c358c9e439 name="ffbd1dda-05d3-48c5-8e12-13c358c9e439"}

DDoS攻撃や無限ループバグによる異常請求を避けるため、必ず料金アラートを設定しましょう。

**設定すべきアラート：**

-   AWS: AWS Budgetsで月額上限の80%、100%、120%でアラート

-   Google Cloud: Billing Budgetsで同様の設定

-   OpenAI API: Usage limitsで月額上限を設定

### 6. エラー監視とログ収集の仕組みを整える {#a4299a82-3fdc-454e-8d37-6e3cd2994f55 name="a4299a82-3fdc-454e-8d37-6e3cd2994f55"}

「動いているから大丈夫」は危険です。水面下で起きている問題を検知する仕組みが必要です。

**推奨ツール：**

-   **Sentry**: エラー検知とパフォーマンス監視

-   **Datadog / New Relic**: 総合的なアプリケーション監視

-   **CloudWatch Logs (AWS)**: AWSサービスのログ集約

ただし、ログにパスワードやクレジットカード番号などの機密情報を出力しないよう、細心の注意を払いましょう。

### 7. 権限管理は「最小権限の原則」を徹底する {#fd986d58-8e47-4c3d-b69c-3155fc4b18cc name="fd986d58-8e47-4c3d-b69c-3155fc4b18cc"}

「誰が何をできるか」を明確に定義し、必要最小限の権限のみを付与しましょう。

**実装例：**

-   一般ユーザー：自分のデータのみ閲覧・編集可能

-   管理者：全データの閲覧可能、編集は一部制限

-   スーパー管理者：全権限（IP制限やVPN経由のみアクセス可）

Firebase AuthenticationやAuth0などの認証サービスを使えば、この実装が比較的簡単になります。

### 8. 個人情報は「触らぬ神に祟りなし」の精神で {#dcd96498-175f-447c-997e-1c9fc999c420 name="dcd96498-175f-447c-997e-1c9fc999c420"}

GDPR（EU一般データ保護規則）や日本の個人情報保護法を考慮すると、個人情報の取り扱いは慎重に慎重を重ねるべきです。

**原則：**

-   必要最小限のデータのみ収集

-   収集目的を明確にし、ユーザーに同意を得る

-   不要になったら速やかに削除

-   データの暗号化（保存時・通信時の両方）

### 9. パスワードの平文保存に注意 {#bfbb655d-aee3-47df-989f-7797866bfdb5 name="bfbb655d-aee3-47df-989f-7797866bfdb5"}

AIが吐き出すコードは基本的にはパスワードを暗号化するようにしているので大丈夫だと思いますが、平文で保存すると万が一個人情報が流出した際に、色々な二次的な被害がユーザーに及んで本当にシャレにならないので気をつけましょう。

javascript

``` {#8ac9bd4e-f9e1-489f-9a45-8b2afbaf8924 data-name="preCode"}
// bcryptを使ったハッシュ化の例
const bcrypt = require('bcrypt');
const saltRounds = 10;
const hashedPassword = await bcrypt.hash(plainPassword, saltRounds);
```

bcrypt、Argon2、scryptなどの安全なハッシュ関数を使い、絶対に独自実装はしないこと。

### 10. 決済機能は「命がけ」で実装する {#f7d254ef-c2eb-4807-9ebc-4fc9b311fbc9 name="f7d254ef-c2eb-4807-9ebc-4fc9b311fbc9"}

決済機能の実装ミスは、金銭的被害に直結します。まじで細心の注意を払いましょう。

**鉄則：**

-   クレジットカード情報を自社サーバーに保存しない

-   Stripe、PayPal、Square等の信頼できる決済代行サービスを利用

-   テスト環境と本番環境のAPIキーを絶対に混同しない

-   決済データとユーザーを突合できるようにしておく

-   Webhookの署名検証を必ず実装

## まとめ：セキュリティは「転ばぬ先の杖」 {#a9bf1302-cad6-450d-8f17-bda85eb64e93 name="a9bf1302-cad6-450d-8f17-bda85eb64e93"}

AIツールによって開発速度が飛躍的に向上した今だからこそ、セキュリティの基本を押さえることが重要です。なお筆者には、7年間のエンジニア経験があり、1億人規模のプラットフォーム開発に従事しておりました。

完璧なセキュリティは存在しませんが、これらの基本を押さえれば、大きな事故は防げるはずです。

バイブコーディングは大いなる力をもたらしますが、セキュリティの事故が起こってからでは遅いです。

皆さんの開発がより安全で、より価値あるものになることを願っています。
