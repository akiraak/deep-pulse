# 記事の多階層化（1記事を複数ページで構成する）

## ユーザー指示

> １つの記事を複数のページで構成する多階層化を行う。
> 書籍の階層構造（章立て・見出し）は、大きい順に「編（へん）」＞「章（しょう）」＞「節（せつ）」＞「項（こう）」と同じものを想定する。
> Web記事の場合は書籍と違う構成が良ければそれも検討する

確認済みの設計判断（ユーザー選択）:

- **ページ分割の単位 = 章**（章ごとに別URL・別ページ）
- **保存形式 = 複数 .md ファイル**（記事ディレクトリ内に章ファイルを並べる）

## 目的

長い記事を「1ファイル = 1ページ」で読ませると、スクロールが長大になり全体像をつかみにくい。
そこで、1つの記事を**章ごとのページに分割**し、書籍のような階層ナビゲーションで読めるようにする。

## 階層モデル（書籍 → Web のマッピング）

書籍の「編＞章＞節＞項」を、Web記事では次のように対応させる。

| 書籍 | Web での扱い | 実体 |
|------|------------|------|
| 編（へん） | ページをまとめる**グループ見出し**（任意） | 章ファイルの frontmatter `part:` で表現。目次・サイドバーの区切りになる |
| 章（しょう） | **1ページ = 1URL** | 1つの章 `.md` ファイル。ページの H1 = 章タイトル |
| 節（せつ） | ページ内の **H2 見出し** | 章ファイル内の `##` |
| 項（こう） | ページ内の **H3 見出し** | 章ファイル内の `###` |

ポイント:

- **「ページ」になるのは章だけ**。編はあくまで章をまとめるラベル（独立ページを持たない）。節・項は章ページ内の見出しで、既存の目次（TOC）サイドバーがそのまま使える。
- 編（`part`）は**任意**。指定しなければ章がフラットに並ぶ。深い階層が不要な記事は編を使わなければよい。
- 1記事が短い場合は**従来どおり単一ページ**でよい（多階層化は任意機能）。

## ディレクトリ構成

### 単一ページ記事（従来形・互換維持）

```
output/YYYY-MM-DD_タイトル/
  YYYY-MM-DD_タイトル.md          # 記事本体（1ページ）
  YYYY-MM-DD_タイトル_plan.md
  YYYY-MM-DD_タイトル_note.md
  sources/
```

これは**一切変更しない**。`chapters/` が無い記事は今までどおりに描画される。

### 多階層記事（新形式）

```
output/YYYY-MM-DD_タイトル/
  YYYY-MM-DD_タイトル.md          # 「扉ページ」= 記事インデックス（リード文＋全体俯瞰）
  chapters/                        # ← このディレクトリの有無で多階層記事と判定する
    01_章タイトルA.md
    02_章タイトルB.md
    03_章タイトルC.md
    ...
  YYYY-MM-DD_タイトル_plan.md
  YYYY-MM-DD_タイトル_note.md
  sources/
```

- **判定ルール**: 記事ディレクトリ内に `chapters/` があり、`.md` ファイルを1つ以上含む場合のみ多階層記事として扱う。無ければ従来の単一ページ。
- **扉ページ（`<dir>.md`）の役割**: 記事のトップページ。次を含む。
  - H1 = 記事タイトル
  - リード文（記事全体の導入）
  - 全体俯瞰セクション（主要プレイヤー表・Mermaid 相関図など、CLAUDE.md の俯瞰セクション規約に従う）
  - **章一覧（目次）は手書きせず、`chapters/` から自動生成して挿入する**
- **章ファイル名**: `NN_章タイトル.md`（`NN` は2桁連番）。連番でページ順を決める。
- **章ファイルの先頭 frontmatter（任意）**:
  ```
  ---
  part: 第1編 基礎編      # 任意。編グループ名。連続する同じ part がグルーピングされる
  title: 章タイトル        # 任意。無ければ本文先頭の H1 から取得する
  ---
  ```
  - `part` は隣接する同名の章をまとめる。`part` が変わると目次に新しいグループ見出しが立つ。
  - frontmatter が無くても動く（章タイトルは本文 H1、編グループ無し）。

## URL / ルーティング

| ページ | URL | 出力ファイル（静的ビルド） |
|--------|-----|--------------------------|
| 記事一覧 | `/` | `index.html` |
| 記事の扉（インデックス） | `/articles/<base>.html` | `articles/<base>.html` |
| 各章 | `/articles/<base>/<NN_章タイトル>.html` | `articles/<base>/<NN_章タイトル>.html` |

- 扉ページの URL は**従来の単一記事と同じ**（`/articles/<base>.html`）。SNS 共有リンク・既存の note リンクは扉を指したまま壊れない。
- 章は記事 base 名のサブパス配下に置く。動的サーバー (`src/server.ts`) に新ルート `^/articles/<base>/<chapter>.html$` を追加する。
- パストラバーサル対策: base・chapter とも `..` と余分な `/` を拒否し、解決後の実パスが `output/<base>/chapters/` 配下に収まることを `path.relative` で検証する（admin.ts の sources 配信と同じ方式）。

## ナビゲーション仕様

### 1. 扉ページ（記事インデックス）

- リード文・全体俯瞰のあとに、**自動生成の目次**を表示する。
  - 編（`part`）ごとにグループ見出しを立て、その下に章リンクを並べる。
  - 各章リンクの下に、章内の節（H2）を**任意で**ぶら下げる（深くなりすぎる場合は章のみ）。→ 実装時に節まで出すか章のみかは Phase 1 で見て決める。
- 「最初の章を読む →」CTA リンクを目次の先頭または末尾に置く。

### 2. 章ページ

- **パンくず**: `記事一覧 / 記事タイトル / 章タイトル`（記事タイトルは扉ページへのリンク）。
- **サイドバー（左、sticky）**: 既存の TOC サイドバーを拡張する。
  - 全章リスト（編でグループ化）を表示し、**現在の章をハイライト**。
  - 現在の章の直下にだけ、その章の節・項（H2/H3）アンカーを展開表示する（他章は章見出しのみ）。
  - 既存 `buildToc()` / `.sidebar` CSS を流用しつつ「章ナビ + 現在章の見出し」を結合した構造にする。
- **前後リンク（フッター）**: `← 前の章（タイトル）` / `次の章（タイトル） →`。先頭章の「前」は扉ページ、末尾章の「次」は無し。
- **読了順**: 扉 → 01 → 02 → … → 最終章、の一直線。

### 3. モバイル

既存の `.toc-mobile`（H1 直下に目次を展開）と同じ方針。章ページでは「この記事の章一覧（折りたたみ）＋現在章の見出し」を H1 直下に出す。サイドバーは非表示（既存のメディアクエリを踏襲）。

## 実装方針（コードの変更点）

### `src/render.ts`（中心）

1. **章の列挙**: 新関数 `listChapters(base)` を追加。
   - `output/<base>/chapters/*.md` を読み、ファイル名連番でソート。
   - 各章の frontmatter（`part` / `title`）をパースし、`title` 未指定なら本文 H1 から取得。
   - 戻り値: `{ filename, slug, title, part, index }[]`。
   - frontmatter パーサは admin.ts の `parseFrontmatter` と同等のものを共通化（`src/frontmatter.ts` に切り出すか、render.ts 内に持つ）。
2. **多階層判定**: `isMultiPage(base)` = `chapters/` に `.md` が1つ以上あるか。
3. **目次生成**: `buildChapterToc(chapters, currentSlug?)` を追加。編グループ・現在章ハイライトに対応。
4. **扉ページ描画**: `renderArticle()` を拡張（または `renderArticleIndex()` を分岐）。多階層記事なら本文の後に自動目次を挿入する。
5. **章ページ描画**: 新関数 `renderChapter(base, chapterFilename, indexHref)`。
   - 章 `.md` を marked で変換（既存の chart/mermaid/heading レンダラーをそのまま使う）。
   - サイドバー = 章ナビ + 現在章の H2/H3。
   - パンくず・前後リンクを組み立てて `wrapHtml()` に渡す。
   - frontmatter は本文から除去してから marked にかける。
6. **`wrapHtml()`**: 前後リンク（footer nav）用のスロットを追加するか、`body` 末尾に組み込む。サイドバーは既存 `tocHtml` 経路を流用。

> 既存のモジュールレベル可変状態（`collectedHeadings` 等）は1ページ描画ごとにリセットされている。章描画でも各章単位で同様にリセットすればよい（並列描画はしていないので安全）。

### `src/server.ts`

- 章ルート `^/articles/(?<base>[^/]+)/(?<chapter>[^/]+)$` を追加し、`.html → .md` 変換 → `renderChapter()` を呼ぶ。
- 扉ページの音声（MP3）配信は現状維持。章ごとの音声は**今回スコープ外**（将来必要なら別タスク）。

### `scripts/build_static.ts`

- 各記事について、多階層なら `chapters/` を走査して `articles/<base>/<slug>.html` を出力する（`articles/<base>/` ディレクトリを作成）。
- 扉ページは従来どおり `articles/<base>.html` に出力（自動目次付き）。
- 単一ページ記事の出力は不変。

### `src/admin.ts`（管理画面ワークスペース）

- `listWorkspaceFiles()` に `chapters/*.md` を「章」グループとして追加表示する（sources と同様の列挙）。
- 右ペイン `handleArticlerender` で `chapters/<name>` を受け付け、`renderChapter()` でプレビューできるようにする。
- 記事一覧のサイズ/ソース数表示は現状維持（必要なら「章数」バッジを追加してもよいが任意）。

### `files.ts`（ファイルビューア・3002）

- `output/` 配下の全 `.md` を素で見るビューアなので、`chapters/*.md` は**自動的に対象に入る**想定。再帰走査の深さだけ確認し、必要なら対応する。

### `CLAUDE.md`（記事生成ルール）

多階層記事の作り方を追記する:

- ディレクトリ構成（`chapters/` と扉ページの役割）
- 章ファイルの命名規則（`NN_章タイトル.md`）と frontmatter（`part` / `title`）
- 編＞章＞節＞項 と H1/H2/H3・ページ分割の対応表
- 「どの記事を多階層にするか」の目安（例: 本文が長く章立てが自然に切れるテーマ。短い記事は単一ページのまま）
- 扉ページに書く内容（リード＋全体俯瞰。目次は自動生成なので手書きしない）
- ファクトチェック・note 生成・ビルド手順は章を含めて行う旨

## 段階的ロールアウト

レイアウト・ルーティング・生成ルールにまたがる大きめの変更なので、まずパイロット1記事で検証する。

### Phase 1: 仕組みの実装 + パイロット記事1本

- `render.ts` / `server.ts` / `build_static.ts` に多階層対応を実装。
- 既存の長い記事を1本選び（候補: `2026-05-22_TheTechnologicalRepublic解読`、`2026-06-10_スティーヴン・キング全作品ガイド` など本文が長いもの）、`chapters/` 形式に再構成して検証する。
  - ※ パイロットに使う具体的な記事はユーザーと相談して決める。
- 検証項目:
  - [ ] 扉ページに章の目次が自動生成・表示される
  - [ ] 各章ページが別URLで開き、本文・Mermaid・Chart.js・テーブルが崩れない
  - [ ] サイドバーに全章リスト＋現在章ハイライト＋現在章の節/項が出る
  - [ ] 前後リンク（前の章／次の章／扉）が正しくつながる
  - [ ] パンくずが `記事一覧 / 記事タイトル / 章タイトル` になる
  - [ ] 動的サーバー（`npm run serve`）と静的ビルド（`npm run build:site`）で同じ表示
  - [ ] **`chapters/` を持たない既存記事が一切変化なく従来どおり描画される**
  - [ ] 記事一覧（`/`）には多階層記事も「1記事1行」で出る（扉ページへのリンク）
  - [ ] モバイル表示が崩れない

### Phase 2: ルール確定・横展開

- Phase 1 の表示と使い勝手に OK が出たら、`CLAUDE.md` に多階層記事の生成ルールを正式に追記する。
- 以後、長い記事は多階層、短い記事は単一ページ、と使い分ける。
- 既存記事の多階層化は必要なものだけ順次行う（一括変換はしない）。

## 互換性・非互換の整理

| 項目 | 影響 |
|------|------|
| 既存の単一ページ記事 | **変更なし**（`chapters/` が無いため従来経路） |
| 既存の URL（`/articles/<base>.html`） | **維持**（扉ページがその URL） |
| note リンク（扉を指す） | **維持** |
| `listArticles()` の一覧 | 1記事1エントリのまま（章は一覧に出さない） |
| TTS 音声 | 当面は扉/単一記事のみ。章ごと音声は別タスク |

## スコープ外（今回はやらない）

- 章ごとの TTS 音声生成
- 章をまたいだ全文検索
- 「編」自体を独立ページにする（深い3階層ページ化）
- ページネーション以外の凝った遷移アニメーション

これらは必要になったら別タスクとして切り出す。
